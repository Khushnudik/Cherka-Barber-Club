# CHERKA — Luxury Black & Gold Barbershop

Одностраничный адаптивный сайт премиального мужского барбершопа на **React, TypeScript, Vite и Tailwind CSS**. Основной индивидуальный дизайн сайта находится в `src/styles.css`, иконки — Lucide. Фотографии, соцсети, отзывы и бизнес-данные сейчас демонстрационные: перед публикацией замените их реальными материалами и ссылками барбершопа.

## Запуск

Требуется **Node.js 20+** и npm:

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite. Для проверки production-сборки:

```bash
npm run build
npm run preview
```

## Публикация сайта на GitHub Pages

Репозиторий автоматически собирает и публикует сайт на GitHub Pages при каждом push в ветку `main` (workflow: `.github/workflows/pages.yml`). После успешного первого запуска Actions сайт будет доступен по адресу:

**https://khushnudik.github.io/Cherka-Barber-Club/**

Если GitHub попросит настроить публикацию, откройте **Settings → Pages** репозитория и выберите **Build and deployment → Source → GitHub Actions**. Сборка Vite настроена на адрес репозитория; локальный `npm run dev` остаётся на корневом адресе.

## Настройка бизнеса

Измените контактные данные, расписание и бренд в `src/site.ts`. Каталог услуг (название, категория, цена, продолжительность, фото), мастеров, отзывы и FAQ отредактируйте в `src/data.ts`. Фотографии сейчас загружаются с Unsplash. Чтобы использовать свои фотографии, разместите их на своём CDN или в `public/images` и поменяйте адреса изображений в каталоге.

## Онлайн-запись: границы текущей версии

Готов мастер из пяти шагов: услуга → барбер/любой мастер → дата → время → имя и телефон. Включены проверка полей, ближайшие 14 дней, часы по бизнес-настройкам, расчёт свободного времени в браузере, индикация недоступных интервалов после локальной записи и экран результата. Повторное сохранение и конфликты проверяются браузером, а не атомарно: только backend может предотвратить две одновременные записи от разных клиентов.

**Бэкенд, база данных и синхронизация между устройствами пока не подключены.** Текущая запись сохраняется только в `localStorage` текущего браузера. Это демонстрация работающего интерфейса, а не подтверждённое бронирование кресла: клиенту явно показывается предупреждение и номер телефона для подтверждения. Данные браузера можно очистить; заявки не поступают администратору. Файл `src/booking.ts` содержит контракт `BookingAdapter` и `createRemoteBookingAdapter`. Для существующего backend укажите URL endpoint в `VITE_BOOKING_API_URL` (например, в локальном `.env.local`). Сервер принимает `POST` с JSON `{name, phone, serviceId, barberId, date, time}`; ответ — JSON `{id, status, barberId}`. Статус `pending` обозначает непроверенную заявку, `confirmed` — только действительно подтверждённую серверную запись; HTTP-ошибки должны возвращать JSON `{error}`. Сервер обязан заново проверить данные каталога и рабочего времени, атомарно зарезервировать свободный интервал и обеспечить права доступа. Перед настройкой endpoint требуется Node.js версии 20 или выше.

## Supabase и админ-панель

Настроенного Supabase-проекта, ключей, схемы БД, авторизации или административной панели **нет**. Поиск сервиса подтвердил, что в доступном каталоге сейчас нет варианта Supabase; поэтому проект не выдаёт локальные данные за настоящую серверную систему. Ни админ-панель, ни реальная синхронизация расписания между посетителями не реализованы. Контракт удалённого API в `src/booking.ts` готов; настроить URL для отправки заявок можно через `VITE_BOOKING_API_URL`, если endpoint уже существует.

Безопасный план внедрения:

1. Создать Supabase-проект и вынести URL/anon key в переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (anon key не заменяет RLS).
2. Добавить таблицы `services`, `barbers`, `working_hours`, `bookings` и таблицу закрытых интервалов. Задать строгие политики RLS, ограничить публичное чтение активных услуг/мастеров, не открывать публичное чтение телефонных номеров и личных данных записей.
3. Вход администратора организовать через Supabase Auth и роль с серверной проверкой; админ-операции и управление графиком разрешать только авторизованным пользователям с этой ролью.
4. Запись отправлять в серверную функцию. На сервере заново рассчитывать цену и длительность из каталога, проверять часы, пересечения записи/перерывы и атомарно резервировать время. Не сохранять телефон в открыто доступной таблице и добавить политику хранения и обработки персональных данных.
5. Реализовать админ-интерфейс управления каталогом, мастерами, графиком и статусами `pending`, `confirmed`, `cancelled`, `completed`. Сменная граница UI–API уже доступна через `BookingAdapter` и `createRemoteBookingAdapter`; API URL в `VITE_BOOKING_API_URL` настраивается для существующего безопасного endpoint, Supabase автоматически не подключается.
6. Только после настройки backend изменить адаптер и текст подтверждения, выполнить проверку разрешений, конкурентного бронирования и сборки перед публикацией.

До подключения и проверки backend не показывайте статус записи как подтверждённую реальным барбершопом и не используйте демонстрационную локальную запись для обслуживания реальных клиентов.
